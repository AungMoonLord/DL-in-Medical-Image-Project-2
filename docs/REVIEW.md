## 2. ข้อสังเกตจากการวิเคราะห์ (ต้องแก้ในสไลด์)

### ⚠️ ข้อสรุปเรื่อง Sphynx → Chihuahua ใน notebook ไม่ถูกต้อง

Notebook ส่วน 4.1 (และหัวข้อ Confusion Matrix ใน `index.html` ซึ่งไม่ได้แก้ตามที่ตกลงไว้) สรุปว่า Sphynx ถูกทายเป็น Chihuahua 12 ภาพ "ทั้งที่ Species Head แทบไม่พลาด" จึงแปลว่าสองหัวไม่สอดคล้องกัน

ตรวจซ้ำรายภาพแล้วพบว่า **ใน 12 ภาพนั้น หัวหมาแมวก็ตอบ "หมา" ด้วย 10 ภาพ** คือผิดพร้อมกันทั้งสองหัว และ 10 ภาพนี้คือแมวส่วนใหญ่ใน 16 ภาพที่หัวหมาแมวพลาด

**ควรพูดในสไลด์ว่า:** Sphynx เป็นจุดอ่อนของ feature ร่วม เพราะแมวไม่มีขน ตัวเล็ก หูใหญ่ จึงดูเหมือนหมา ทั้งสองหัวจึงพลาดไปด้วยกัน ส่วนกรณีที่สองหัวขัดกันจริงมีแค่ 10 ภาพทั้งชุด (คำตอบฉบับเต็มอยู่ใน `web/qa.html`)


### ⚠️ ตาราง 3 รูปแบบในเซลล์ที่ 6 ไม่ตรงกับ checkpoint ที่ได้รับ

ได้รับ checkpoint ของ Seg-focused และ Cls-focused แล้ว (`best_model_resnet50_seg2.0_cls0.5.pth`, `best_model_resnet50_seg0.5_cls2.0.pth`) config ใน checkpoint ตรงกับ Balanced ทุกค่า ยกเว้น λ ตามที่ตั้งใจ ประเมินทั้ง 3 โมเดลบนภาพชุดเดียวกัน (CPU, fp32) ได้ผลดังนี้

| รูปแบบ | λ seg : breed : species | epoch ที่เลือก | Test mIoU | Test Dice | Test Breed Acc | Test Breed F1 | Test Species Acc |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| Balanced | 1.0 : 1.0 : 0.5 | 10 | **0.8266** | **0.8987** | 91.66% | 91.51% | 99.51% |
| Seg-focused | 2.0 : 0.5 : 0.5 | 28 | 0.8234 | 0.8965 | 92.64% | 92.48% | 99.78% |
| Cls-focused | 0.5 : 2.0 : 0.5 | 27 | 0.8222 | 0.8957 | **93.08%** | **92.98%** | **99.81%** |

| ค่าใน notebook เซลล์ที่ 6 | Test mIoU | Test Breed F1 | Test Breed Acc |
|---|:---:|:---:|:---:|
| Seg-focused (notebook) | 0.8285 | 0.8942 | 89.65% |
| Cls-focused (notebook) | 0.8094 | 0.9168 | 91.82% |

**ตัวเลขของ 2 รูปแบบไม่ตรงกับ notebook เลย** และทิศทางของข้อสรุปกลับด้าน

- Notebook (และหัวข้อ "ทดลอง 3 แบบ" ใน `index.html` ซึ่งไม่ได้แก้ตามที่ตกลงไว้) สรุปว่า "เน้นงานไหน งานนั้นดีขึ้นเล็กน้อย แต่อีกงานเสียมาก Balanced คุ้มที่สุด"
- จาก checkpoint จริง **ทั้งสองรูปแบบจำแนกสายพันธุ์ได้ดีกว่า Balanced อย่างมีนัยสำคัญ** และ **mIoU ต่ำกว่า Balanced เล็กน้อยทั้งคู่** แม้แต่ Seg-focused ที่ให้น้ำหนัก segmentation เป็น 2 เท่า

**ทดสอบความต่างแบบจับคู่บน test (ภาพเดียวกัน 3,669 ภาพ):**

| เทียบกับ Balanced | Δ mIoU (95% CI, bootstrap 1,000 รอบ) | Δ Breed Acc (95% CI) | McNemar (Breed) |
|---|---|---|---|
| Seg-focused | −0.0032 (−0.0042 ถึง −0.0022) | +0.98 pts (+0.33 ถึง +1.69) | Balanced ถูกคนเดียว 64 · Seg-focused ถูกคนเดียว 100 · p = 0.006 |
| Cls-focused | −0.0044 (−0.0053 ถึง −0.0035) | +1.42 pts (+0.68 ถึง +2.10) | Balanced ถูกคนเดียว 59 · Cls-focused ถูกคนเดียว 111 · p < 0.001 |

**ตีความ:**

1. **ตัวแปรกวน (confound): epoch ที่เลือกต่างกันมาก** Balanced ถูกเลือกที่ epoch 10 (LR ยังสูง ~8e-5) ส่วนอีกสองแบบถูกเลือกที่ epoch 27–28 (LR ใกล้ 1e-6 โมเดลลู่เข้าแล้ว) ความได้เปรียบด้านการจำแนกของสองแบบหลังจึงน่าจะมาจาก "เทรนจนจบ" มากกว่ามาจาก λ ข้อนี้อธิบายได้ว่าทำไม Seg-focused จำแนกเก่งกว่า Balanced ทั้งที่ λ_breed ต่ำกว่า
2. **การเลือกโมเดลหลักยังถูกต้องตามขั้นตอน** บน Val ซึ่งเป็นชุดที่ใช้ตัดสิน คะแนน (mIoU + Breed F1) ÷ 2 ของ Balanced = 0.8863 สูงกว่า Cls-focused 0.8842 และ Seg-focused 0.8832 การเลือก Balanced เป็นแบบหลักจึงยืนได้ ห้ามเปลี่ยนไปเลือกแบบอื่นเพราะผล test ดีกว่า (นั่นคือการใช้ test เลือกโมเดล)
3. **Val กับ Test ไม่สอดคล้องกัน** บน Val Seg-focused มี mIoU สูงสุด (0.8230 vs 0.8186) แต่บน Test ต่ำกว่า Balanced แสดงว่า Val 736 ภาพเล็กเกินไปสำหรับความต่างระดับ 0.003–0.004
4. **ความต่างด้าน segmentation มีนัยสำคัญทางสถิติแต่เล็กมากในทางปฏิบัติ** (0.3–0.4 จุด) ส่วนความต่างด้านการจำแนก (1–1.4 จุด หรือราว 36–52 ภาพ) มีความหมายกว่า

### 3.1 จุดเสี่ยงหลัก: "เปรียบเทียบอย่างน้อย 3 รูปแบบ"

- ทั้ง 3 รูปแบบเป็นสถาปัตยกรรมเดียวกัน ต่างแค่ λ กรรมการอาจตีความว่าเป็นการจูน hyperparameter ไม่ใช่ "3 รูปแบบ"
- ตอนนี้ได้ checkpoint ครบทั้ง 3 แบบและตรวจซ้ำได้แล้ว แต่ตัวเลขไม่ตรงกับ notebook และการเปรียบเทียบมีตัวแปรกวนเรื่อง epoch (ดูข้อ 2)
- **ข้อแนะนำ (ถ้ามีเวลาเทรนเพิ่ม):**
  1. เพิ่ม backbone ResNet-34 (`configs/config.py` รองรับอยู่แล้ว ใช้ `BACKBONE="resnet34"`) เป็นการเทียบสถาปัตยกรรมที่ชัดเจน
  2. เพิ่ม single-task baseline (seg อย่างเดียว / breed อย่างเดียว) ตอบคำถาม "Multi-task ดีกว่าจริงไหม" ได้โดยตรง
  3. ประเมินทั้งสามแบบที่ epoch เดียวกัน เพื่อให้เทียบผลของ λ ได้อย่างเป็นธรรม
- ถ้าไม่มีเวลา: ในสไลด์ให้เรียกว่า "การทดลองเปรียบเทียบกลยุทธ์ถ่วงน้ำหนัก Loss 3 รูปแบบ" และอธิบายว่าเป็นการทดลองแบบควบคุมตัวแปรเดียว

| 8 | README อ้าง Albumentations แต่โค้ดใช้ `torchvision.transforms` และตัวอย่างคำสั่งอ้างโฟลเดอร์ `Inference_Image_Data/` ที่ไม่มีแล้ว | `README.md` | ผู้อ่านสับสน | **แก้แล้ว** ในรอบนี้ |

### สิ่งที่ตรวจแล้วถูกต้อง

- ลำดับ `BREED_NAMES` ตรงกับ CLASS-ID ใน `annotations/list.txt` (และป้ายของ torchvision) ทั้ง 37 คลาส
- `CAT_BREEDS` ครบ 12 สายพันธุ์ ตรงกับคอลัมน์ SPECIES
- การแปลง trimap 1/2/3 → 1/0/2 ถูกต้อง · Mask ใช้ NEAREST ทั้งตอน resize และ rotate · มุมที่หมุนแล้วว่างถูกเติมเป็นพื้นหลัง
- ColorJitter ทำเฉพาะภาพ · Val/Test ไม่มี augmentation
- `train.py` ไม่โหลด test loader มาใช้ · checkpoint เลือกด้วย Val
- Dice loss คำนวณจาก softmax (หาอนุพันธ์ได้) และเฉลี่ยทุกคลาส
