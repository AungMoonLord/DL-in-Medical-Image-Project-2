Q&A · การนำเสนอและตอบคำถาม 3 คะแนน

คำถามที่คาดว่าจะเจอ และแนวคำตอบ

รวบรวมจากจุดที่กรรมการน่าจะสงสัย จุดอ่อนที่เรารู้อยู่แล้ว และเรื่องที่เอกสารประกอบการสอนเน้น กดที่คำถามเพื่อดูแนวคำตอบ ส่วน "เคล็ดลับ" คือสิ่งที่ควรพูดเพิ่มหรือควรระวัง

หลักการตอบ
  • ตอบตรงคำถามก่อนในประโยคแรก แล้วค่อยให้เหตุผล
  • ยกตัวเลขจากงานจริงทุกครั้งที่ทำได้ ตัวเลขทั้งหมดในหน้านี้ตรวจซ้ำจาก checkpoint แล้ว
  • ถ้าเป็นจุดที่ไม่ได้ทดลอง ให้บอกตรง ๆ ว่ายังไม่ได้ทดลอง แล้วเสนอวิธีทดสอบ
  • เหตุผลเชิงลึกของแต่ละองค์ประกอบอยู่ในหน้า เจาะลึกองค์ประกอบ
โจทย์และข้อมูล
ทำไมต้องทำ Multi-task ในโมเดลเดียว ไม่แยก 3 โมเดล

เพราะทั้ง 3 งานต้องการ "ความเข้าใจภาพสัตว์" ชุดเดียวกัน การใช้ encoder ร่วมจึงประหยัดกว่าเกือบครึ่ง โมเดลเรามี 48.8 ล้านพารามิเตอร์ ถ้าแยก 3 โมเดลจะราว 95.8 ล้าน และต้องรัน encoder 3 รอบต่อภาพ

อีกเหตุผลคือ Multi-task เป็นประเภทงานที่ได้คะแนนความยากสูงสุด 4 คะแนน และเราประเมินแต่ละงานแยกกันตามเงื่อนไขของเกณฑ์

เคล็ดลับ: อย่าอ้างว่า Multi-task ทำให้แม่นขึ้น เพราะเราไม่มี single-task baseline มาเทียบ ให้พูดว่า "ประหยัดกว่า และได้ผลระดับเดียวกับงานทั่วไปที่ใช้ ResNet-50"

ทำไมใช้ Test 3,669 ภาพ (50%) ซึ่งเยอะกว่าปกติ แทนที่จะเอาไปเทรนเพิ่ม

เป็นการแบ่งทางการของชุดข้อมูล (Parkhi et al., 2012) ใช้แบบเดียวกันทำให้ผลของเราเทียบกับงานอื่นได้ และไม่มีใครสงสัยว่าเราเลือก test ให้ง่าย

Test ขนาดใหญ่ทำให้ตัวเลขนิ่ง ความต่าง 1% เท่ากับราว 37 ภาพ ส่วนข้อมูลเทรน 2,944 ภาพ (ราว 80 ภาพต่อสายพันธุ์) เพียงพอเพราะเราใช้ transfer learning จาก ImageNet

รับประกันได้อย่างไรว่าไม่มี Data Leakage
  • Test มาจากรายชื่อ test.txt ทางการ ไม่ซ้ำกับ trainval.txt และไม่ถูกโหลดใน train.py เลย
  • Val แบ่งจาก trainval เท่านั้น และเป็นชุดเดียวที่ใช้เลือก checkpoint
  • Augmentation ทำเฉพาะ train ส่วน Val/Test ทำแค่ Resize + Normalize
  • ตาราง 3 รูปแบบบน test ใช้รายงานผลเท่านั้น Balanced ถูกกำหนดเป็นแบบหลักตั้งแต่ก่อนเทรน

เคล็ดลับ: ถ้าถูกถามเรื่อง ImageNet ให้ยอมรับว่า ImageNet มีหมาแมวหลายสายพันธุ์ ช่วยให้ transfer learning ได้ผลดี แต่ไม่ใช่การรั่วของ test ของเรา

ข้อมูลไม่สมดุลไหม แก้อย่างไร
  • สายพันธุ์: สมดุลดี ราว 200 ภาพต่อสายพันธุ์ (น้อยสุด Bombay 184 ภาพ) จึงใช้ CE ธรรมดาได้
  • หมา:แมว: ราว 2.1 : 1 (4,978 : 2,371) จึงรายงาน Precision/Recall/F1 แยกรายคลาสและ Macro F1 ไม่ใช่ Accuracy อย่างเดียว
  • ระดับพิกเซล: โดยเฉลี่ยพื้นหลังกินพื้นที่ 58% ตัวสัตว์ 30% ขอบแค่ 12% และเป็นแถบบางที่เรียนยาก จึงเพิ่ม Dice loss ที่ให้ทุกคลาสมีน้ำหนักเท่ากัน
คลาส "ขอบ" (Boundary) คืออะไร ทำไมต้องทำนายด้วย

ในไฟล์ trimap ค่า 3 คือ "Not classified" เป็นแถบรอบตัวสัตว์ที่คนทำเฉลยไม่แน่ใจว่าเป็นตัวสัตว์หรือพื้นหลัง เราเลือกทำนายเป็นคลาสที่ 3 เพื่อให้โมเดลเรียนรู้ว่าขอบอยู่ตรงไหน

ผลข้างเคียงคือ mIoU ถูกดึงลง (IoU ขอบ 0.637) บางงานวิจัยเลือกไม่คิดบริเวณนี้หรือรวมกับตัวสัตว์ ค่าที่เทียบกับงานอื่นได้ตรงกว่าจึงเป็น IoU ของตัวสัตว์ 0.896

โมเดล
ทำไมเลือก ResNet-50 ไม่ใช่ VGG, EfficientNet หรือ ViT

เอกสาร DLMed-08 ให้เลือก backbone จากความแม่น ความเร็ว และขนาด ResNet-50 อยู่จุดสมดุล ในกราฟของเอกสารได้ top-1 ราว 74.5% ที่เวลาประมวลผลราว 3.5 เท่าของ SqueezeNet ขณะที่ VGG แม่นน้อยกว่าและช้ากว่าเกือบ 2 เท่า

ResNet-50 มี 5 stage ที่ให้ feature หลายความละเอียดพอดีกับ skip connection ของ U-Net และมีน้ำหนัก ImageNet ใน torchvision พร้อมใช้ ส่วน EfficientNet และ ViT ยังไม่ได้ลอง เป็นงานต่อยอด

ทำไมใช้ U-Net ไม่ใช่ DeepLab หรือ Mask R-CNN

U-Net ใช้ skip connection ส่งรายละเอียดจาก encoder ไปช่วย decoder ทำให้ขอบคม ซึ่งจำเป็นกับคลาสขอบที่เป็นแถบบาง และเป็นสถาปัตยกรรมหลักในบทเรียน segmentation (DLMed-12) ที่ออกแบบมาเพื่อภาพทางการแพทย์

DeepLab เด่นเรื่องบริบทหลายสเกล เหมาะกับฉากที่มีวัตถุหลายขนาด ภาพของเรามีสัตว์ตัวเดียวเป็นหลัก ส่วน Mask R-CNN เป็น instance segmentation ที่ต้องมีขั้นตรวจจับวัตถุก่อน ซับซ้อนเกินโจทย์

Skip connection คืออะไร ถ้าไม่มีจะเกิดอะไรขึ้น

คือการนำ feature จาก encoder ระดับเดียวกันมาต่อกับ decoder ตอนขยายภาพ Encoder ย่อภาพจนเหลือ 7×7 รู้ว่า "อะไร" แต่ลืมว่า "อยู่ตรงไหน" skip connection ส่งข้อมูลตำแหน่งความละเอียดสูงกลับมา

ถ้าไม่มี decoder ต้องเดารายละเอียดจาก 7×7 อย่างเดียว ขอบจะเบลอเป็นก้อน (เราไม่ได้ทดลองตัด skip ออก แต่นี่คือผลที่บทความ U-Net และ DLMed-12 อธิบายไว้)

หัวทายหมาแมวกับหัวทายสายพันธุ์ ตอบขัดกันได้ไหม

ขัดกันได้ในทางทฤษฎี เพราะโจทย์กำหนดให้สองหัวแยกกัน แต่ในทางปฏิบัติแทบไม่เกิด จาก test 3,669 ภาพ สองหัวตอบขัดกันแค่ 10 ภาพ (0.27%) เพราะทั้งสองหัวรับ feature ชุดเดียวกันจาก encoder

กรณี Sphynx (แมว) ที่ถูกทายเป็น Chihuahua 12 ภาพ ตรวจซ้ำแล้วพบว่า หัวหมาแมวก็ตอบ "หมา" ด้วยใน 10 ภาพ คือผิดพร้อมกันทั้งสองหัว ไม่ใช่ตอบขัดกัน และ 10 ภาพนี้คือที่มาส่วนใหญ่ของแมว 16 ภาพที่หัวหมาแมวทายผิด แปลว่าปัญหาอยู่ที่ feature ร่วม (แมวไม่มีขน ตัวเล็ก หูใหญ่ ดูเหมือนหมา) ไม่ใช่ที่หัว

ถ้าอนุมานหมาแมวจากหัวสายพันธุ์แทน จะได้ 99.45% ใกล้เคียงหัวหมาแมว (99.51%) หน้า ทดลองโมเดล แสดงคำเตือนเมื่อสองหัวขัดกัน

เคล็ดลับ: notebook ส่วน 4.1 และหัวข้อ Confusion Matrix ด้านบนสรุปจากกรณี Sphynx ว่า "สองหัวไม่ได้ตรวจคำตอบกัน" ซึ่งข้อมูลไม่สนับสนุน ให้ใช้คำอธิบายในข้อนี้แทนเมื่อถูกถาม

การเทรน
Loss รวมกันอย่างไร และค่า λ มาจากไหน

\(\mathcal{L} = \lambda_{seg}(\mathcal{L}_{CE}+\mathcal{L}_{Dice}) + \lambda_{breed}\,\mathcal{L}_{CE}^{\,ls} + \lambda_{sp}\,\mathcal{L}_{CE}\) ค่าหลักคือ λ = 1.0 : 1.0 : 0.5 ตั้งจากเหตุผล ไม่ได้ค้นหาอัตโนมัติ งานหลักสองงานได้น้ำหนักเท่ากัน ส่วนหมาแมวง่ายและเรียนเสร็จเร็วจึงได้ครึ่งเดียว

เราทดลองเปลี่ยน λ 3 รูปแบบ ผลจาก checkpoint จริง: สองแบบที่ปรับ λ จำแนกสายพันธุ์ได้ดีกว่า Balanced 1.0–1.4 จุด (มีนัยสำคัญ) และ mIoU ต่ำกว่าเล็กน้อย 0.003–0.004 แต่ส่วนหนึ่งมาจาก epoch ที่ถูกเลือกต่างกัน (Balanced epoch 10, อีกสองแบบ epoch 27–28) ดูข้อ "ทำไมไม่เลือกแบบที่ผล test ดีกว่า"

เคล็ดลับ: ถ้าถูกถามว่าทำไมไม่ใช้ λ อัตโนมัติ ให้ตอบว่า Uncertainty weighting (Kendall et al., 2018) เป็นงานต่อยอดที่วางแผนไว้

ทำไมใส่ Dice loss เพิ่ม ใช้ Cross-Entropy อย่างเดียวไม่พอหรือ

CE คิดทุกพิกเซลเท่ากัน คลาสพื้นหลังที่มีพิกเซลมากจึงครอบงำ loss ส่วน Dice วัดสัดส่วนการทับซ้อนของแต่ละคลาสแล้วเฉลี่ย คลาสขอบที่เล็กจึงมีน้ำหนักเท่าพื้นหลัง DLMed-12 ระบุว่า Dice ช่วย "โดยเฉพาะเมื่อข้อมูลไม่สมดุล"

ใช้คู่กันเพราะ CE ให้ gradient นิ่งตั้งแต่ต้น ส่วน Dice อย่างเดียวมักแกว่งช่วงแรก

Label smoothing คืออะไร ทำไมใช้กับสายพันธุ์อย่างเดียว

แทนที่จะบอกโมเดลว่าคำตอบถูกมั่นใจ 100% เราให้เป้าหมายเป็นราว 95% และกระจาย 5% ที่เหลือให้คลาสอื่น (\(y_{true} = 1-\varepsilon+\varepsilon/K \approx 0.951\), \(\varepsilon = 0.05,\ K = 37\)) โมเดลจึงไม่มั่นใจเกินเหตุ เหมาะกับสายพันธุ์ที่หน้าคล้ายกันจนคนยังแยกยาก เช่น American Pit Bull กับ Staffordshire

หมาแมวแยกง่ายและไม่กำกวม จึงไม่จำเป็น

Checkpoint ที่ใช้มาจาก epoch 10 จาก 30 แล้วอีก 20 epoch เสียเปล่าไหม

เราเก็บ epoch ที่ (Val mIoU + Val Breed F1) ÷ 2 สูงสุด ซึ่งเป็น epoch 10 (0.8856) เพราะ Breed F1 บน Val กระโดดเป็น 0.9526 epoch 11–30 ได้ 0.872–0.883 รอบที่ดีที่สุดต่ำกว่า epoch 10 แค่ 0.003 และ mIoU ยังขึ้นช้า ๆ ถึง 0.8217

Val มีราว 20 ภาพต่อสายพันธุ์ ภาพเดียวเปลี่ยน recall ของสายพันธุ์นั้นได้ 5% การเลือก epoch จึงมีสัญญาณรบกวน ไม่ได้แปลว่าโมเดลแย่ลงหลัง epoch 10 ทางแก้คือใช้ Val ใหญ่ขึ้น หรือเฉลี่ยน้ำหนักหลาย epoch

โมเดล Overfit ไหม ดูจากอะไร

ไม่เห็นสัญญาณชัด Val loss ลดจาก 1.67 แล้วนิ่งที่ราว 0.91–0.95 โดยไม่เด้งกลับขึ้น และ Val mIoU กับ F1 ไม่ลดลงช่วงท้าย

Train loss (0.60) ต่ำกว่า Val loss แต่เทียบตรง ๆ ไม่ได้ เพราะ train loss คิดขณะมี augmentation และ dropout ส่วนที่ช่วยกัน overfit คือ pretrained weights, augmentation, dropout, weight decay และ label smoothing

bfloat16 คืออะไร ทำให้ความแม่นยำลดลงไหม

เป็นตัวเลข 16 บิตที่มีช่วงค่ากว้างเท่า fp32 แต่ทศนิยมน้อยกว่า ใช้ผ่าน torch.autocast เฉพาะตอนคำนวณ ส่วนน้ำหนักโมเดลยังเก็บเป็น fp32 จึงไม่กระทบความแม่นยำอย่างมีนัยสำคัญ แต่เร็วขึ้นและใช้ VRAM น้อยลง

ต่างจาก fp16 ที่ช่วงค่าแคบ ต้องใช้ GradScaler กัน gradient ล้น ส่วน bf16 ไม่ต้อง

ถ้ารันเทรนใหม่จะได้ผลเท่าเดิมไหม

การแบ่งข้อมูลเหมือนเดิมทุกครั้ง (seed 42) แต่ผลเทรนอาจต่างเล็กน้อย เพราะยังไม่ได้ตั้ง seed ให้ PyTorch และ augmentation และเปิด cuDNN benchmark ไว้เพื่อความเร็ว

เพราะเหตุนี้ความต่างระหว่างรูปแบบที่เล็กมาก เช่น mIoU ต่างกัน 0.003–0.004 ควรยืนยันด้วยการเทรนหลาย seed แล้วรายงานค่าเฉลี่ย ± ส่วนเบี่ยงเบน การทดสอบแบบจับคู่ที่เราทำ (McNemar, bootstrap) บอกได้ว่าความต่างไม่ใช่ความบังเอิญจากการสุ่มภาพ test แต่ยังบอกไม่ได้ว่าไม่ใช่ความบังเอิญจากการสุ่มตอนเทรน

ผลลัพธ์และการวิเคราะห์
ผล 91.7% ดีแค่ไหน เมื่อเทียบกับงานอื่น

บทความต้นฉบับของชุดข้อมูล (Parkhi et al., 2012) ได้ความแม่นจำแนก 37 สายพันธุ์ราว 59% ด้วยวิธีก่อนยุค deep learning ส่วนงานที่ fine-tune CNN สมัยใหม่ขนาดใกล้ ResNet-50 ที่ 224×224 มักได้ราว 88–93% (เช่น Kornblith et al., 2019) ผลของเราจึงอยู่ในระดับที่คาดหวังได้

เคล็ดลับ: อย่าอ้างว่า "ดีที่สุด" โมเดลใหญ่หรือภาพละเอียดกว่าได้สูงกว่านี้ ให้เน้นว่าเราได้ผลนี้พร้อมทำ segmentation ไปด้วยในโมเดลเดียว

ทำไม mIoU (0.827) ต่ำกว่า Dice (0.899) ตัวไหนถูก

ถูกทั้งคู่ วัดสิ่งเดียวกันด้วยสูตรต่างกัน \(\text{Dice} = \dfrac{2\,\text{IoU}}{1+\text{IoU}}\) จึงสูงกว่า IoU เสมอเมื่อไม่ทับกันสนิท เช่น IoU ขอบ 0.637 แปลงเป็น Dice ได้ 0.778

งาน segmentation ทั่วไปนิยม IoU ส่วนงานภาพทางการแพทย์นิยม Dice เราจึงรายงานทั้งสองค่า

Cls-focused จำแนกสายพันธุ์ได้ดีกว่า Balanced บน test ทำไมไม่เลือกแบบนั้น

เพราะเกณฑ์เลือกโมเดลที่กำหนดไว้ก่อนคือคะแนน (mIoU + Breed F1) ÷ 2 บน Val และ Balanced ได้สูงสุด (0.8863 เทียบกับ Cls-focused 0.8842 และ Seg-focused 0.8832) ถ้าเปลี่ยนไปเลือกแบบที่ test ดีกว่า เท่ากับใช้ข้อสอบจริงตัดสินซึ่งเป็น data leakage แบบหนึ่ง

ตัวเลข test ใช้รายงาน trade-off: Cls-focused ทายสายพันธุ์ถูกมากกว่า 1.4 จุด (ราว 52 ภาพ, McNemar \(p < 0.001\)) แต่ mIoU ต่ำกว่า 0.004 ส่วนสาเหตุหลักน่าจะเป็นเพราะ checkpoint ของ Cls-focused มาจาก epoch 27 ที่เทรนจนลู่เข้าแล้ว ขณะที่ Balanced มาจาก epoch 10

เคล็ดลับ: ความไม่สอดคล้องระหว่าง Val กับ Test (บน Val Seg-focused มี mIoU สูงสุด แต่บน Test ต่ำสุดอันดับสอง) เป็นหลักฐานว่า Val 736 ภาพเล็กเกินไปสำหรับความต่างระดับนี้ พูดเรื่องนี้เป็นข้อจำกัดได้เลย

โมเดลสับสนสายพันธุ์ไหนมากที่สุด และเพราะอะไร

อันดับ 1 คือ American Pit Bull Terrier → Staffordshire Bull Terrier 29 ภาพ (และกลับด้านอีก 13) สองสายพันธุ์นี้ต่างกันหลัก ๆ ที่ขนาดตัวและสัดส่วน ซึ่งดูจากภาพเดี่ยวที่ไม่มีวัตถุอ้างอิงขนาดได้ยาก ตามด้วย Egyptian Mau → Bengal (แมวลายจุดทั้งคู่) และ Ragdoll → Birman (แมวขนยาวแต้มสีตาฟ้า)

ข้อผิดพลาดส่วนใหญ่จึงเป็นคู่ที่คนทั่วไปก็แยกยาก ไม่ใช่โมเดลมองผิดจุด ดูลักษณะเด่นของแต่ละสายพันธุ์ได้ที่หน้า ทำความรู้จักข้อมูล

ถ้าใส่ภาพที่ไม่ใช่หมาหรือแมว หรือสายพันธุ์ที่ไม่มีในชุดข้อมูล จะเกิดอะไรขึ้น

โมเดลจะตอบ 1 ใน 37 สายพันธุ์เสมอ เพราะเป็น closed-set classification เช่นภาพหมาอากิตะถูกทายเป็นชิบะด้วยความมั่นใจ 97.6% แสดงว่าความมั่นใจสูงไม่ได้แปลว่าถูก

ทางแก้คือการตรวจจับภาพนอกคลาส (out-of-distribution detection) เช่นตั้ง threshold ความมั่นใจ หรือเพิ่มคลาส "อื่น ๆ"

ข้อจำกัดใหญ่ที่สุดของงานนี้คืออะไร
  • ไม่มี single-task baseline จึงพิสูจน์ไม่ได้ว่า Multi-task ช่วยให้แม่นขึ้น
  • เทรนแต่ละรูปแบบครั้งเดียว ความต่างเล็ก ๆ ระหว่างรูปแบบอาจเป็นความบังเอิญ
  • ภาพถูกย่อเหลือ 224×224 และบีบให้เป็นสี่เหลี่ยมจัตุรัส รายละเอียดขอบหายไป และวัด IoU ที่ความละเอียดนี้ ไม่ใช่ความละเอียดเดิม
  • Closed-set: ตอบได้แค่ 37 สายพันธุ์ และภาพที่ทายผิดยังมีความมั่นใจเฉลี่ยถึง 71% (ภาพที่ทายถูก 93%)

เคล็ดลับ: การบอกข้อจำกัดเองก่อนถูกถามเป็นส่วนหนึ่งของคะแนน "วิเคราะห์ผลและข้อจำกัด"

การนำไปใช้และวิชานี้
งานภาพสัตว์เลี้ยงเกี่ยวกับภาพทางการแพทย์อย่างไร

โครงสร้างเดียวกันใช้กับภาพทางการแพทย์ได้ตรง ๆ เช่น segment ก้อนเนื้อพร้อมจำแนกชนิด หรือ segment ปอดพร้อมคัดกรองโรค U-Net ก็ถูกออกแบบมาเพื่อภาพทางการแพทย์ตั้งแต่ต้น

สิ่งที่ต้องปรับคือ ภาพแพทย์มักเป็นขาวดำหรือ 3 มิติ ขณะที่ backbone ImageNet รับ RGB 3 ช่อง และโดเมนต่างจาก ImageNet มาก DLMed-08 จึงแนะนำ fine-tuning มากกว่า feature extraction สำหรับงานแพทย์

โมเดลเร็วแค่ไหน ใช้งานจริงได้ไหม

วัดบนโน้ตบุ๊ก (CPU, PyTorch fp32, ทีละภาพ) ได้ราว 160 ms ต่อภาพ สำหรับทั้ง 3 งานพร้อมกัน และบนเบราว์เซอร์ด้วย WebGPU ราว 0.4 วินาที ส่วน WASM ราว 1.6 วินาที ประเมิน test ทั้ง 3,669 ภาพบน CPU ใช้ราว 11 นาที

เพราะ encoder รันครั้งเดียวแล้วแชร์ให้ทั้ง 3 งาน จึงเร็วกว่ารัน 3 โมเดลแยกกัน ขนาดไฟล์โมเดลสำหรับใช้งาน (ONNX) ราว 186 MB
